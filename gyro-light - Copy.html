ESP32 · ESP-NOW · Onshape

Gyro-Controlled Task Light

A wearable controller reads how I tilt my hand and sends it over wireless to a motorized base that mirrors the motion.

Prototype, in progress

SHEET 1

Where it stands

The electronics and control system work. The wireless link is reliable, the sensor reads tilt well, and the servos move smoothly after tuning.

The mechanical side is rough. The first printed base is a basic prototype, and the pan servo stalls because the tilt assembly rests its weight on it. The fix is a thrust bearing, and I have not added it yet. No light is mounted either. For now the base carries a dovetail clip where a light or other tool can attach later.

WorksWireless link, sensing, servo control, power
Needs workPan axis load, printed base finish, light head
SHEET 2

How it works

Wearable

An ESP32 with an MPU6050 motion sensor and a button. It reads tilt and filters out sensor noise.

Wireless

ESP-NOW sends tilt values between the two ESP32 boards. It needs no router and no pairing.

Base

A second ESP32 turns the values into pan and tilt angles for two servos and moves them in small steps.

The button works as a clutch. Hold it to aim, release it to freeze the aim, then re-grip and keep going. This also gets around the sensor's lack of left-right tracking.

Most failures were not where they first looked. The upload failure looked like code and was a driver. The hot servo looked electrical and was a weight problem. Testing each part alone, and spinning the mechanism by hand with the power off, is what found the real causes.

SHEET 6

Planned improvements

  • Add a thrust bearing on the pan axis. This is the direct fix for the stall.
  • Check pan servo torque afterward and move to a stronger servo if needed.
  • Mount a light head on the dovetail and test it.
  • Consider a laser attachment, with careful eye-safety handling because the aim is motorized.
  • Build a soldered permanent version once the mechanics are settled.
  • Route wires through the printed post with strain relief at every moving joint.
SHEET 7

Devlog

July 2026Entry 001: Project kickoffPlanning

Scoped a two-axis motorized base, a gyro-based wearable controller, a swappable mount and a lock function that freezes the current angle. Compared servos with steppers and chose hobby servos for simplicity. Chose ESP-NOW for the wireless link because it needs no router or pairing and is built into the ESP32.

Parts ordered: 2 ESP32 boards, an MPU6050 motion sensor, 2 MG90S metal-gear servos, a breadboard and jumper kit, push buttons and power banks.

August 2026Entry 002: Software setup and first uploadIn progress

Installed the Arduino IDE and ESP32 board support. The board would not show up as a COM port, and uploads failed with "No serial data received." I ruled out the BOOT button trick, swapped cables (some were charge-only) and finally found the cause in Device Manager. The board sat under "Other devices" as an unrecognized CP2102 USB bridge. Installing the Silicon Labs CP210x driver fixed it, and Blink then ran on both boards.

Lesson: driver problems look like code or wiring problems. Check Device Manager first.

August 2026Entry 003: Wireless link provenWorking

Wrote a minimal sender and receiver. One board sends a counter and the other prints it. I had to find each board's MAC address and put it in the sender. A newer ESP32 core changed the callback signature, which caused one compile error. With both Serial Monitors side by side, the numbers matched in real time. This proved the wireless link before any sensors or motors were involved.

August 2026Entry 004: Gyro wired and reading dataWorking

Soldered header pins onto the MPU6050 and wired its four lines (VCC, GND, SDA, SCL) to the wearable ESP32. A test sketch showed values changing as I tilted the sensor. I also wired the lock button on its own pin and tested it by itself first.

August 2026Entry 005: Servos wired and sweepingWorking

Wired both servos to the base ESP32 with signal on two pins and power and ground on shared rails. A sweep test from 0 to 90 to 180 degrees ran smoothly before I connected anything else.

August 2026Entry 006: First live control and tuningWorking, needed tuning

Combined the sensor, wireless link and servos. Tilting the sensor moved the servos on the first try. Testing then turned up three problems:

  • Pan and tilt were swapped, so I corrected which sensor axis drives which servo.
  • The lock button worked backwards. I changed it so holding the button moves the light and releasing it freezes the aim, like lifting a mouse to reposition it.
  • Motion was too fast and jerky. I switched to writeMicroseconds() for finer control, added a smoothing filter on the sensor data and capped how far the servo can move per update.
August 2026Entry 007: Known limit, no yawDocumented

The MPU6050 has no magnetometer. It senses tilt well but cannot sense left-right spin, and its yaw estimate drifts. I did not add hardware. The hold-to-move button covers it, because I can move, release, reposition and move again.

August 2026Entry 008: Printed base and pan/tilt bracketIn progress

Designed the first base and the pan/tilt bracket in Onshape, then sliced and printed them. Onshape was new to me, and this project was how I learned it. I added a dovetail mount to the bracket so different tools, such as a light, can be swapped on later. No light is mounted yet.

August 2026Entry 009: Pan servo stalls and runs hotIssue found

During testing the pan servo ran hot and moved slowly. I powered off right away. Turning the plate by hand with the power off took real effort, so the cause was mechanical.

Root cause: the tilt servo, bracket and attachment rest their full weight on the pan servo's shaft. The servo has to hold the load up as well as turn it, so it draws high current and stalls.

Planned fix: add a thrust bearing or small lazy-susan bearing under the rotating plate so the servo only turns the load. If torque is still low, move to a stronger pan servo.

August 2026Entry 010: Power setup for nowWorking
  • Wearable controller: a small power bank into the ESP32 USB port.
  • Base ESP32: wall adapter into its USB port.
  • Servos: a second power bank through a stripped USB-C cable wired to the 5 V and ground rails.

The base ESP32 and the servos run from different supplies, so their grounds must be tied together for the signal wires to work.

SHEET 8

Tools and AI use

I built, wired, soldered, tested and debugged this project myself. I used Claude, an AI assistant from Anthropic, as a resource along the way. It explained unfamiliar ideas such as I2C, ESP-NOW and servo control, and it helped me write and debug the Arduino code, which I then tested and changed based on what the hardware did. It also helped make the diagrams and draft the devlog and write-up from my build notes.

The CAD work was done in Onshape. I had never used CAD before this project, so building these parts was also how I learned the software.
